            <summary>Read full writeup</summary>

              <p>

                Sensor data moves over ESP-NOW because nodes do not need to stay connected to a WiFi router just to send readings. Firmware updates come over standard WiFi and HTTP. The gateway coordinates everything, printing sensor data to the serial monitor and serving as the control hub.

                <strong>Gateway</strong><span>ESP32 Dev Module — coordinates network</span>

                <strong>Node 2</strong><span>ESP32 Dev Module — simulated data</span>

              </div>

              <p><strong>How rollback works:</strong> The ESP32 bootloader uses two flash partitions. New updates download to the inactive partition while the old version keeps running. If the new code crashes or fails a checksum check, the bootloader switches back to the working partition automatically.</p>

              <p>To prove it worked, I tested three versions: v1 baseline, v2 with a new serial output message, and v3 which deliberately crashes on startup. Pushing v3 successfully forced the device to roll back to v2 by itself.</p>
